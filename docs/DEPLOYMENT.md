# Развёртывание

У проекта два разных способа запуска: статический сайт с документацией
и серверная игровая арена. Их можно размещать независимо.

## GitHub Pages

На Pages публикуются лендинг, плавная фоновая шахматная сцена и
документация. Аккаунты и реальные партии здесь не выполняются.

```sh
npm ci
npm run build:pages
npm run preview:pages
```

Сборка лежит в `out/`. Локальный просмотр по умолчанию доступен на
http://127.0.0.1:4173/DeepMove/. Проверяются и относительные пути проекта.

### Автоматическая публикация

Workflow `.github/workflows/pages.yml` собирает сайт и публикует артефакт
через официальный GitHub Pages deployment:

1. В репозитории открой **Settings → Pages → Source → GitHub Actions**.
2. Изменения `main`, затрагивающие сайт, документацию или сборку, запускают
   публикацию. Есть и ручной `workflow_dispatch`.
3. Workflow использует права `contents: read`, `pages: write`,
   `id-token: write` и окружение `github-pages`.
4. Результат доступен на **https://kait20-dev.github.io/DeepMove/**.

В `out/` загружаются только публичные файлы. Не назначай корень репозитория
артефактом Pages: там есть исходники, служебные файлы и локальные данные.

Руководство GitHub: [custom workflows for Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

### Изменение адреса

Для другого репозитория обнови URL проекта в `scripts/build-pages.mjs`,
canonical / Open Graph в `site/index.html` и ссылки README. Относительные
ссылки внутри сайта продолжат работать. Собственный домен при необходимости
настраивается в Pages отдельно.

## Серверная арена

Нужны Node.js 24+, постоянный диск и один процесс приложения. Запускай
команды из корня репозитория:

```sh
npm ci
npm run build
npm start
```

По умолчанию сервер слушает `127.0.0.1:3000`. Для доступа извне используй
reverse proxy с HTTPS. Он направляет запросы на локальный порт приложения.
Stockfish запускается на сервере из `node_modules/stockfish/bin`.

### Конфигурация

| Переменная | Назначение |
| --- | --- |
| `APP_ORIGIN` | Точный публичный HTTPS-origin, например `https://arena.example.org` |
| `DEEPMOVE_DB` | Абсолютный путь к SQLite на постоянном диске |
| `PORT` | Порт сервера Next.js при необходимости |

Пример для PowerShell:

```powershell
$env:APP_ORIGIN = 'https://arena.example.org'
$env:DEEPMOVE_DB = 'C:\DeepMoveData\deepmove.sqlite'
npm start
```

Пример для Linux:

```sh
export APP_ORIGIN=https://arena.example.org
export DEEPMOVE_DB=/var/lib/deepmove/deepmove.sqlite
npm start
```

Адрес `arena.example.org` в примерах — заполнитель, не действующий сервер.
Не помещай пользовательскую БД во временную файловую систему контейнера
или serverless-функции без постоянного диска.

## Резервное копирование

SQLite работает в WAL-режиме. Для простой файловой копии останови процесс
приложения и скопируй БД вместе с существующими `-wal` и `-shm`. Для
работающего сервера используй совместимый с SQLite online backup tool.
Просто копировать один файл активной БД недостаточно.

Перед обновлением сделай резервную копию. Новые поля добавляются миграциями
при открытии БД; ручное удаление таблиц не требуется.

## Проверка установки

1. Главная и `/arena` открываются без ошибок.
2. Регистрация, вход и сохранение профиля проходят на выбранном origin.
3. Два клиента могут занять места и сыграть тестовую партию.
4. Зритель видит игру, но не может управлять чужим местом.
5. PGN скачивается, после завершения запускается локальный анализ.
6. После перезапуска сервера партия, профиль и сессии сохранились.

Завершай реальные партии перед обслуживанием: их часы продолжаются и
после отключения процесса. Для автоматизации проверок смотри
[Contributing](../CONTRIBUTING.md).
