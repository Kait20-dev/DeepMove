# DeepMove — подключение к игровой арене

## Модель доверия

Боты работают на компьютерах участников и вызывают HTTP API. Арена не принимает исполняемые файлы, URL движков или пользовательский код. Сервер хранит позицию, проверяет ходы с помощью chess.js, определяет результат и считает время. Клиент не может задавать позицию, результат, цвет или остаток времени.

PGN — формат записи партии; FEN — текущая позиция; UCI (`e2e4`, `a7a8q`) — формат отправки одного хода. SAN (`Nf3`, `O-O`) генерируется сервером.

Обязателен HTTPS для удалённых подключений. Локальная разработка: `http://127.0.0.1:3000`. Версия реализации API: 1, префикс `/api/arena`.

## Как начать

1. Создать профиль и войти на `/arena`.
2. Создать партию, выбрать тип своего места «Бот», тип соперника и формат времени.
3. Передать сопернику ссылку на партию **и отдельно** код приглашения. Одна ссылка даёт только просмотр. Соперник входит в собственный аккаунт и занимает свободное место по коду. Один аккаунт не может занять обе стороны одной партии.
4. Каждый владелец места бота нажимает «Выпустить ключ бота». Ключ показывается только в ответ на выпуск, хранится на сервере как SHA-256 и относится к одной стороне одной партии. Новая выдача немедленно отзывает старый ключ. Ключ не хранится в localStorage и не передаётся в URL.
5. Запустить свой процесс клиента, подтвердить готовность запросом `ready` и опрашивать состояние. После готовности двух сторон начинается обратный отсчёт (по умолчанию 8 секунд). Часы запускаются после него. Человек готов сразу после занятия места.

Код приглашения можно перевыпустить до начала партии; старый перестанет работать. Не публикуйте ключи в исходниках, логах, PGN и скриншотах. При передаче боту используйте переменную окружения или скрытый ввод.

## Состояние партии

`GET /api/arena` возвращает лобби `{user, games, teams}`. `games` — до 50 кратких карточек `{id, createdAt, status, result, reason, format, seats, moveCount}`. Полная история, PGN и анализ загружаются только по конкретному ID, чтобы опрос лобби не блокировал приём ходов. Секретных полей в карточках нет; переход старта и таймауты по-прежнему определяет сервер.

`GET /games/ID` — без авторизации, JSON с заголовком `Cache-Control: no-store`.

| Поле | Смысл |
| --- | --- |
| `id` | UUID партии |
| `status` | `waiting`, `playing`, `finished` |
| `result` | `*`, `1-0`, `0-1`, `1/2-1/2` |
| `reason` | `checkmate`, `timeout`, `resignation`, `stalemate`, `repetition`, `insufficient_material`, `fifty_moves`, `cancelled` |
| `timeout` | При `finished/timeout`: `{side, kind: "move" или "total", ply, limitMs, remainingMs, deadlineAt?, lateMove?}`, иначе null. `ply` — номер непринятого полухода с 1, `limitMs` — доступное время на него, `remainingMs` — общий остаток в момент дедлайна |
| `fen` | Текущая позиция, включая очередь, рокировки, en passant |
| `turn` | `w` или `b` |
| `legalMoves` | Все легальные UCI-ходы; пустой массив вне активной партии |
| `moves` | История `{uci, san, fen, elapsedMs, remainingMs}` |
| `seats.w`, `seats.b` | `{userId, name, kind, ready}` без секретов |
| `clocks.w`, `clocks.b` | Остатки общего времени на начало текущего хода, мс |
| `turnStartedAt` | Серверное Unix-время начала текущего хода, мс; null вне игры |
| `startDelayMs` | Длительность обратного отсчёта после готовности двух сторон, мс |
| `startsAt` | Серверное Unix-время запланированного старта, мс; null до готовности |
| `deadline` | Момент, до которого сервер должен принять ход, мс |
| `serverNow` | Серверное время снимка, мс |
| `format` | `{name, initialMs, incrementMs, botMoveMs, humanMoveMs?}`; отсутствие humanMoveMs означает отсутствие отдельного лимита у человека |
| `version` | Версия состояния; растёт при игровых изменениях |
| `pgn` | Запись PGN текущей или завершённой партии |
| `analysis` | Готовый разбор или null; только для завершённых партий |
| `material` | Суммарный материал и взятые фигуры |

Действующий остаток активной стороны: `max(0, clocks[turn] - (serverNow - turnStartedAt))`. `deadline` учитывает **оба** ограничения: общий запас и максимум одного хода бота. Для собственного таймера отсчитывайте прошедшее от получения ответа монотонными часами; сервер остаётся авторитетом.

`reason=timeout` сохраняется для совместимости. `timeout.kind=move` означает превышение лимита отдельного хода, даже если общий запас положительный; `total` — исчерпание общего запаса (включая совпадение обоих дедлайнов). Время считается до принятия хода сервером, включая доставку запроса. Просроченный ход не добавляется в SAN/PGN: время последнего записанного хода относится к предыдущему принятому ходу. Для старых партий сведения о таймауте восстанавливаются из сохранённых часов.

Новые таймауты сохраняют `deadlineAt` — точное Unix-время дедлайна в мс. Когда приходит первый легальный ход просрочившей стороны с правильным `expectedPly`, сервер сохраняет `lateMove: {uci, receivedAt, delayMs}`. `receivedAt` фиксируется сервером после получения и разбора полного JSON, до учётных операций БД; `delayMs = receivedAt - deadlineAt`. Заголовки запроса и клиентские поля времени не учитываются. Граница строгая: ход ровно в дедлайн уже просрочен, `delayMs=0`. Повторные, чужие, нелегальные и устаревшие попытки не меняют запись. Это работает и после того, как таймаут зафиксировал зритель. Результат, часы и список принятых ходов остаются прежними. Само время обнаружения таймаута не является величиной опоздания.

Если `lateMove` отсутствует, поздний допустимый ход не получен: точное опоздание и причину отсутствия запроса определить нельзя. В старых архивах нет измерения позднего запроса — интерфейс явно сообщает об этом. PGN сохраняет `TimeoutDeadlineAt` и, если есть поздний ход, `LateMove`, `LateMoveReceivedAt`, `LateMoveDelayMs` как дополнительные заголовки; поздний ход не попадает в игровую последовательность.

В повторе часы обеих сторон показывают остатки непосредственно после выбранного хода: последнее `remainingMs` этой стороны или `format.initialMs`, если она ещё не ходила. Добавление уже включено в `remainingMs`. Кнопка «В конец партии» показывает часы завершения, в том числе расход на непринятый ход. Для таймаута PGN дополнительно содержит `TimeoutSide`, `TimeoutKind`, `TimeoutPly`, `TimeoutLimitMs`, `TimeoutRemainingMs`; стандартные `[%clk]` и `[%emt]` сохраняются для принятых ходов.

Публичные снимки могут читать зрители. Живой интерфейс с анимациями опрашивает сервер раз в секунду; при выключении анимаций или prefers-reduced-motion — каждые 200 мс, сразу показывая последнюю позицию без очереди ходов. Настройка сохраняется локально в браузере и не влияет на серверные часы. Ботам рекомендуется 200–500 мс; не запускайте несколько конкурирующих клиентов для одного места. В этой версии используется HTTP polling, не WebSocket.

## Команды бота

Все POST: `Content-Type: application/json` и `Authorization: Bearer SECRET`. Cookie не нужен. Bearer-ключ не даёт доступ к профилю, командам, приглашениям и ключам другой стороны.

### Готовность

```http
POST /api/arena/games/ID/ready
Authorization: Bearer SECRET
Content-Type: application/json

{}
```

Готовность доступна только до старта. После готовности обоих игроков сервер сохраняет `startsAt = serverNow + startDelayMs`. Во время отсчёта статус остаётся `waiting`, `turnStartedAt` и `deadline` равны null, `legalMoves` пуст, часы не расходуются, ходы отклоняются с 409. Повторный ready не сдвигает старт. Продолжайте опрос — клиент не должен самостоятельно запускать часы. При первом запросе после startsAt сервер переводит игру в playing, считая время именно от сохранённого startsAt; позднее чтение или перезапуск сервера не даёт отсрочку. После перезапуска клиента сначала прочитайте состояние: если игра уже идёт, `ready` не вызывается. Если передан ключ не той партии/стороны, получите 403.

### Ход

```http
POST /api/arena/games/ID/move
Authorization: Bearer SECRET
Content-Type: application/json

{"move":"e2e4","expectedPly":0}
```

`expectedPly = state.moves.length`. Это защита от дубликатов и запросов для устаревшей позиции. Превращение **обязательно** задаётся последней буквой `q`, `r`, `b` или `n`; сервер не выбирает ферзя молча.

Ответ — новое состояние. Если лимит уже истёк, сервер возвращает finished/timeout без применения хода. Если HTTP-ответ потерян, нельзя слепо повторять ход: прочитайте состояние и проверьте длину истории. При 409/stale_position обновите состояние. Чужая очередь — 403, нелегальный ход — 422; такие запросы не сбрасывают дедлайн и не добавляют время.

### Сдача

`POST /games/ID/resign`, JSON `{}`. Требуется ключ этого места или сессия владельца. В активной игре поражение; до старта — отмена без сыгранного результата, `reason=cancelled`.

## Контроль времени

| Формат | Общий запас | Добавление | Ограничение одного хода |
| --- | --- | --- | --- |
| `arena` | 10 минут каждому | 0 | Боту 3 секунды; человеку отдельный лимит не задан |
| `hardbullet` | **15 секунд каждому** | **0** | **1 секунда на ход и боту, и человеку** |
| `rapid` | 10 минут каждому | 0 | Нет, одинаковые условия для людей и ботов |
| `blitz` | 3 минуты каждому | 2 секунды за принятый ход | Нет |
| `custom` | 30–7200 секунд | 0–60 секунд | Боту 1–60 секунд или null |

Это **не** традиционный 10+3 в режиме arena. Три секунды — верхняя граница длительности хода, не прибавка к часам. Дедлайн включителен со стороны поражения: ход, поступивший ровно в дедлайн, уже просрочен. Сетевая задержка и время обработки до взятия серверной транзакции входят в лимит. Заканчивайте расчёт с запасом минимум 200 мс.

**HardBullet Arena** создаётся через `POST /games` с `format: "hardbullet"` (не custom). Сервер задаёт 15000 мс каждому, botMoveMs=1000, humanMoveMs=1000 и incrementMs=0; клиент не может переопределить их полями своего формата. После готовности обоих игроков работает обычный отсчёт; игровые 15 секунд в него не входят. Дедлайн — минимум оставшегося общего времени и одной секунды на текущий ход. Это верхний предел, а не добавление. Боты продолжают ориентироваться на deadline/serverNow, сохраняя запас на передачу; при коротком остатке уменьшают поиск. PGN содержит TimeControl="15+0", BotMoveLimit="1" и HumanMoveLimit="1". Старые партии и форматы без humanMoveMs сохраняют прежние правила.

Сервер не принимает клиентские timestamps и не ставит игру на паузу при отключении. Результат просрочки вычисляется из сохранённого времени при ближайшем чтении или действии; наличие открытой вкладки не требуется. При перезапуске время простоя сервера также расходует часы. Для турнира с другой политикой нужен отдельный регламент остановки сервера.

Мат завершает партию; пат, недостаточный материал, трёхкратное повторение и правило 50 ходов автоматически дают ничью. При просрочке у стороны с одним королём нет возможности победить, результат будет ничейным. Проверка возможности мата по времени консервативная; редкие блокированные позиции, где мат невозможен при достаточном формальном материале, требуют отдельного арбитража. Предложения ничьей в первой версии не предусмотрены.

## Сессии и остальные endpoints

Браузерная регистрация: `POST /register {handle,name,password}`, вход: `POST /login {handle,password}`. Логин 3–30 латинских букв, цифр или `_`, пароль 10–128 символов. В ответе сервер устанавливает HttpOnly/SameSite=Strict cookie на 7 дней; по HTTPS в production — Secure. Пароли хешируются scrypt с индивидуальной солью. Восстановление пароля и подтверждение почты пока отсутствуют.

Cookie-запросы на запись требуют точного `Origin`, совпадающего с `APP_ORIGIN` (или origin запроса при локальном запуске). CORS с других сайтов не разрешён. `POST /logout {}` отзывает текущую сессию.

- `GET /` — текущий публичный профиль, последние 50 партий и до 100 команд.
- `GET /me` — текущий профиль или null.
- `POST /profile {name,bio}` — редактировать собственный профиль; bio до 500 символов.
- `POST /games {format,side,kind,opponentKind,engineName?,startDelaySeconds?}` — создать партию. `side` = w/b, типы = human/bot. Задержка старта — целое число 3–120 секунд, по умолчанию 8. Возвращает снимок и одноразово показываемый `joinCode`. Для custom также `initialSeconds`, `incrementSeconds`, `botMoveSeconds` (число или null).
- `POST /games/ID/join {joinCode,engineName?}` — занять пустое место, только другой аккаунт.
- `POST /games/ID/invite {}` — новый код приглашения; только создатель, только до начала.
- `POST /games/ID/key {}` — новый `{token}`; только владелец места бота.
- `POST /teams {name}` — создать команду, возвращает `{id,invite}`.
- `POST /teams/join {invite}` — вступить по коду.
- `POST /teams/ID/invite {}` — сменить код; только владелец.
- `POST /teams/ID/leave {}` — покинуть команду; владелец выйти не может.

Членство в команде **не** даёт управления партиями другого участника. Команды — профили состава, без общего ключа и турнирного рейтинга.

## PGN и анализ

`GET /games/ID/pgn` скачивает UTF-8 PGN: Event, Site, Date, Round, White, Black, Result, TimeControl, BotMoveLimit, Termination, SAN-ходы, комментарии `[%clk h:mm:ss.sss]` и `[%emt seconds]`. BotMoveLimit — расширение DeepMove. Ходовые записи формирует сервер из принятых легальных ходов.

`POST /games/ID/analysis {}` — любой авторизованный пользователь, только после завершения; результат кэшируется в SQLite и публично доступен в снимке. Одновременно один разбор в Node-процессе. До 400 полуходов, до 120 секунд на партию. Stockfish 19 Lite запускается **локально отдельным дочерним процессом**, без внешнего API. На позицию — глубина до 12 или 30 000 узлов; 32 МБ hash. Процесс завершается после разбора и при ошибках.

Оценки приводятся к белой стороне; положительная — преимущество белых. `mate` хранит расстояние до мата с положительным знаком для белых, отрицательным для чёрных. Внутренний эквивалент мата большой, график обрезает диапазон ±8 пешек. Потери считаются относительно оценки до и после хода и ограничиваются 1000 cp.

Отчёты `version=2` используют обозначения: `??` — зевок, `?` — неточность, 👍 — хороший, ★ — лучший, 📖 — теоретический, `!` — замечательный, `!!` — бриллиантовый. Базовые границы потери: ≤15 cp — лучший, ≤50 — хороший, ≤250 — неточность, >250 — зевок. Точность DeepMove — среднее `100 × exp(−loss/150)`, **не** формула Chess.com.

📖 требует совпадения всей последовательности с префиксом одного из 10 явных дебютных продолжений и потери ≤50 cp. Любой ранний ход автоматически теоретическим не считается. Каталог используется только в разборе, боты его не получают.

`!` требует потери ≤15 cp и совпадения с лучшим ходом движка; лучший другой легальный ход отдельно проверяется Stockfish через `searchmoves`. Разница ≥150 cp, оценка выбранного хода со стороны игрока ≥−100 cp, альтернативы <+100 cp. Единственный легальный ход не получает эту отметку.

`!!` — жертва фигуры стоимостью ≥3, фактически принятой на следующем ходу: материальный баланс относительно начала ухудшается минимум на 2 пешки, потеря оценки исходного хода ≤20 cp, после принятия жертвы оценка ≥−100 cp и снижение относительно начала ≤75 cp. У игрока должно быть несколько легальных ходов. Поддерживаются и жертвы другой фигуры, например уход из-под связки с отдачей ферзя. Равный размен, простое предложение жертвы без взятия и потеря фигуры без компенсации под критерий не подходят. Это ограниченные по глубине эвристики DeepMove, а не точное воспроизведение чужой классификации. Стоимость: p=1, n=3, b=3, r=5, q=9.

Старые отчёты сохраняют свои метки (`mistake` отображается как неточность, `brilliant-candidate` явно остаётся кандидатом). В «График и статистика» есть «Обновить разбор» для авторизованных пользователей; POST пересчитывает старый отчёт и сохраняет `version=2`. Текущая версия повторно берётся из кэша.

Экран партии укладывает доску, часы, список ходов и перемотку в высоту окна. Длинная запись прокручивается отдельно. Взятые фигуры и материальный перевес рядом с игроками привязаны к выбранной позиции; это не оценка Stockfish. Вертикальная шкала берёт оценку только из готового анализа текущего полухода, учитывает переворот доски и мат. В живой игре, без отчёта и до первого хода она нейтральная с «—». Подробности результата, таймаут и опоздание доступны через ⓘ; подключение/ключи/материал — во вкладке «Партия». Перемотка: ←/→, Home/End, кнопки и ползунок; стрелки внутри доски и полей ввода сохраняют своё назначение.

## Ошибки и лимиты

Ошибка JSON: `{"error":"Позиция устарела. Обновите состояние.","code":"stale_position"}`.

| HTTP | Значение |
| --- | --- |
| 400 / 413 / 415 | Неправильный ввод / тело >64 КиБ / неверный Content-Type |
| 401 / 403 | Нет действующей авторизации / нет прав |
| 404 | Партия или ресурс не найден |
| 409 | Неверное состояние или устаревшая позиция |
| 422 | Нелегальный ход или превышен размер партии для разбора |
| 429 | Лимит запросов/занятый анализатор; ответ содержит Retry-After |
| 503 | Анализатор временно недоступен |

Базовые лимиты: 300 POST/мин на ключ бота, 180 записей/мин на аккаунт, 20 созданий/час, 5 одновременно незавершённых партий; 4 запроса анализа/час на аккаунт; 10 попыток входа/15 мин на логин, 100 auth-запросов/мин суммарно, 40 регистраций/час. Публичные чтения ограничены 12 000/мин на весь экземпляр. Это базовая защита, не замена внешнему rate limiting на reverse proxy.

## Ограничения безопасности

Ключи защищают игровые места, а сервер — правила и время. Удалённый протокол **не доказывает** авторство алгоритма, отсутствие готового движка или сторонних подсказок. Для официальных матчей организаторам нужен аудит исходников, проверяемая сборка и изолированные контейнеры/VM с лимитами CPU/RAM/сети. Пользовательский код никогда не должен исполняться в процессе Next.js.

Первый сервер рассчитан на один Node-экземпляр, локальную SQLite WAL и постоянный диск; транзакции `BEGIN IMMEDIATE` сериализуют ходы. Для нескольких реплик нужны общий координатор часов/заданий, база и очередь. Не размещать SQLite на эфемерном serverless-диске. Перед публикацией установить `APP_ORIGIN`, HTTPS, лимиты reverse proxy и резервное копирование. Публичный запуск не выполнялся.
