# DeepMove BotKit

Общая библиотека для **DeepNeuroBot** и **DeepPatternBot**, не отдельный бот.
Четыре движка проекта: DeepMoveBot, DeepSpeedBot, DeepNeuroBot, DeepPatternBot.

Содержит поиск с подключаемой оценкой, базовую ручную оценку, 21 признак
позиции, атомарное сохранение JSON и защищённый HTTP-коннектор.
Поиск, базовая оценка и транспорт основаны на авторском коде DeepMoveBot;
оригинальная папка DeepMoveBot остаётся самостоятельной и не зависит от BotKit.
Новые движки разделяют инфраструктуру, но имеют разные обучаемые модели и политики.

Установка из корня репозитория в **локальное виртуальное окружение**:

```sh
python -m venv .venv-bots
# Windows PowerShell:
.venv-bots/Scripts/python.exe -m pip install -e ./clients/python -e ./DeepNeuroBot -e ./DeepPatternBot
# Linux/macOS:
.venv-bots/bin/python -m pip install -e ./clients/python -e ./DeepNeuroBot -e ./DeepPatternBot
```

В runtime нужны только Python 3.10+ и `chess==1.11.2`. GPU, PyTorch,
TensorFlow, компиляторы и готовые шахматные движки не используются.

`Engine(..., evaluator=callback)` принимает целое число сантипешек с точки
зрения стороны, которой предстоит ход. При смене модели создавай новый Engine.
Он очищает таблицу транспозиций перед каждым поиском и сохраняет историю для повторений.
`FEATURE_VERSION=1` фиксирует порядок и масштаб признаков в JSON-моделях.

Коннектор передаёт `expectedPly`, сверяет FEN, историю и легальные ходы с
сервером, вычитает RTT и резерв из дедлайна. Секрет вводится скрыто или через
`DEEPMOVE_BOT_TOKEN`; редиректы запрещены, удалённое подключение требует HTTPS.
Повторный запрос после сбоя начинается с чтения состояния сервера.
Это клиентские меры; решения о легальности, результате и времени принимает арена.
Коннектор подключает **одну партию**; ключ серии не является ключом партии.
Сначала получи параметры текущей игры через API серии, описанный в
[протоколе](../../docs/BOT_API.md).

Для тестов транспорта и поиска также установи оригинальный пакет
`python -m pip install -e ./DeepMoveBot` в то же окружение: тестовый набор
повторно использует его проверки, не изменяя оригинальные файлы.

```sh
python -m unittest discover -s clients/python/tests -v
```

Проверка двух новых CLI через настоящую арену, после `npm run build`:

```sh
node clients/python/scripts/arena-smoke.mjs
```

По умолчанию используется `.venv-bots`; другой Python можно указать в
`DEEPMOVE_BOT_PYTHON`. Тест поднимает отдельный сервер на 3129 и отдельную БД
в `test-results/learning-bots`, проводит 12 полуходов и завершает партию
явной тестовой сдачей. Пользовательские партии и базу не использует,
обучение не запускает. Это проверка подключения, не замер силы.
