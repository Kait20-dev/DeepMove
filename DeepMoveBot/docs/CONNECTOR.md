# Подключение DeepMoveBot и своих алгоритмов

Этот пакет самодостаточен. Коннектор находится в `src/deepmove_bot/connector.py` и работает с HTTP API арены; он не импортирует код родительского проекта и не требует доступа к серверной базе. Подробная серверная спецификация — [`../../docs/BOT_API.md`](../../docs/BOT_API.md).

## Подготовка

1. Открыть арену `/arena`, создать свой профиль.
2. Создать партию: выбрать свой цвет, тип своего места **Бот**, тип соперника и формат. Для основного теста подходит «Арена · 10 мин / бот ≤3 с».
3. Назвать своего игрока `DeepMoveBot`. Передать второму участнику адрес партии и отдельный код приглашения. Если соперник — человек, он входит со своим профилем и занимает свободное место. Если бот — его владелец выпускает собственный ключ и запускает второй клиент.
4. В панели своего места нажать «Выпустить ключ бота». Сохранить секрет. Ключ даёт право играть только одной стороной одной партии; новый ключ отменяет старый.
5. Запустить процесс, указав UUID партии и цвет своего места. Ключ вводится скрытым приглашением. Параметра `--token` нет: секрет не должен попадать в список процессов, shell history или URL.

Пример для PowerShell, из папки DeepMoveBot:

```powershell
.\.venv\Scripts\python.exe -m deepmove_bot play --url http://127.0.0.1:3000 --game GAME_UUID --side w
```

Для автоматизации допустима переменная окружения `DEEPMOVE_BOT_TOKEN`, переданная процессу средствами вашей среды. Не записывайте её в репозиторий и не публикуйте вместе со зрительской ссылкой. В примере журнала выводятся только выбранные ходы, оценки, глубина, число узлов и длительность поиска.

Для удалённой арены нужен окончательный HTTPS origin: `--url https://arena.example`. HTTP разрешён только для localhost/127.0.0.1/::1. Редиректы отклоняются, чтобы Bearer-ключ не ушёл на другой адрес.

## Цикл протокола

```text
GET /api/arena/games/ID
    ↓ waiting, мой бот не готов
POST /api/arena/games/ID/ready   Authorization: Bearer KEY
    ↓ оба готовы — обратный отсчёт, статус пока waiting, часы не идут
GET /api/arena/games/ID
    ↓ наступил startsAt — сервер запускает часы
GET /api/arena/games/ID
    ↓ playing и моя очередь
восстановить доску из всей истории, сверить FEN/очередь/легальные ходы
посчитать локальный монотонный дедлайн с запасом на сеть
choose_move(Turn) → UCI-строка
POST /api/arena/games/ID/move    {"move":"e2e4","expectedPly":0}
    ↓ снова читать сервер; finished — выход
```

`ready` вызывается только до начала. Цвет в командной строке должен соответствовать ключу. Коннектор обнаруживает несовпадение на этапе ready, если в ответе своё место осталось неготовым. Если место уже готово, окончательную проверку прав при ходе выполняет сервер.

Опрос по умолчанию — раз в 200 мс. У бота есть право только на ready/move/resign; клиент не может задавать позицию, часы и результат. Зрительский GET не содержит секретов.

После готовности обоих игроков действует задержка старта: по умолчанию 8 секунд, при создании партии можно выбрать 3–120. В этот период `status=waiting` и `startsAt` содержит серверное время старта. Существующий клиент совместим: он продолжает опрос и не отправляет ход до `playing`. Повторный ready не продлевает отсчёт. Отдельная искусственная задержка первого хода не нужна и расходовала бы игровой лимит.

### Форматы

- `arena`: 600 секунд каждому; боту максимум 3 секунды на один ход, без добавления. У человека — только общий запас.
- `rapid`: 600 секунд каждому, отдельного лимита хода нет у обоих типов игроков.
- `blitz`: 180 секунд и добавление 2 секунды за принятый ход.
- `custom`: параметры из снимка сервера.

Сетевой транзит входит в серверный лимит. Отключение не ставит игру на паузу. При нехватке времени снижайте `--max-think`, увеличивайте `--reserve`; точные формулы в [FORMULAS.md](FORMULAS.md#8-время).

## Интерфейс собственного алгоритма

Минимальное подключение выглядит так:

```python
import getpass
from deepmove_bot.connector import ArenaClient, Turn

def choose_move(turn: Turn) -> str:
    board = turn.board             # chess.Board с полной историей
    seconds = turn.seconds_left     # оставшийся безопасный бюджет сейчас
    # Здесь ваш собственный поиск. Возвращайте только легальный UCI.
    return next(iter(board.legal_moves)).uci()

client = ArenaClient(
    "http://127.0.0.1:3000",
    "00000000-0000-4000-8000-000000000000",  # заменить UUID
    getpass.getpass("Ключ бота: "),
    "w",
)
final = client.play(choose_move)
print(final["result"], final["reason"])
```

Runnable-пример со случайным легальным ходом: [`examples/custom_algorithm.py`](../examples/custom_algorithm.py). Он демонстрирует транспорт; основной DeepMoveBot использует отдельный математический движок.

`Turn` содержит:

| Поле | Значение |
| --- | --- |
| `board` | Полная проверенная история в `chess.Board`; коннектор создал её для текущего хода |
| `state` | Исходный JSON сервера: часы, moves, legalMoves, format, version и т.д. |
| `deadline` | Локальный монотонный дедлайн с вычетом RTT и сетевого запаса |
| `seconds_left` | Свойство, вычисляющее остаток заново при каждом чтении |

Возвращаемая строка: `e2e4`, `e1g1`, `a7a8q`, `a7a8n` и т.д. Превращение указывайте явно. Не меняйте `state`; если алгоритму нужно менять доску, используйте `board.copy(stack=True)` или гарантированно парные push/pop. Сам DeepMoveBot ищет на копии.

## Обработка ошибок

После потерянного ответа на ход клиент **читает состояние**, а не вслепую повторяет POST: сервер мог уже принять ход. `expectedPly = len(state["moves"])` защищает от дубликатов и устаревших позиций.

- 409: обновить состояние; не повторять старый ход для нового полухода.
- 429: уважать Retry-After, предупредить пользователя. Часы в этот момент продолжают идти.
- 5xx/сетевая ошибка: короткая пауза, затем новое чтение.
- 401/403/404/422: завершить клиент с ошибкой; проверить ключ, сторону, UUID и алгоритм.
- finished/timeout: сервер зафиксировал просрочку; ход после дедлайна не применяется.

Некорректный FEN, несовпадающая история или список легальных ходов приводят к `ProtocolError`. Клиент не запрашивает подсказки анализатора и не использует готовый разбор партий для выбора хода.

## Чего транспорт не обещает

Это клиент на стороне участника, не песочница и не защита от чужого кода. Правила, итог и время окончательно проверяет сервер. Клиентский программный дедлайн мягкий, поэтому полностью исключить просрочку на перегруженной ОС или медленной сети он не может. Внешний алгоритм также обязан соблюдать выделенное время.

При завершении клиента Ctrl+C соединение закрывается, но партия не сдаётся и часы не останавливаются. Явная сдача: `client.request("resign", {})`. Локальное прерывание намеренно не отправляет такую команду без вашего решения.
