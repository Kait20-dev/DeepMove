# Математика DeepMoveBot

Все коэффициенты выбраны вручную. Нет обученных весов, нейросетей, дебютной базы, эндшпильных таблиц или обращений к другому движку. Правила и генерация ходов предоставляются библиотекой `chess`; далее описан собственный алгоритм из `evaluation.py` и `search.py`.

## 1. Единицы и ориентация

Оценка измеряется в сантипешках, `100 cp ≈ 1 пешка`. Положительная статическая оценка `E_white` выгодна белым. В поиске используется перспектива стороны, которая должна ходить:

```text
s = +1, если ход белых; иначе −1
E_stm(P) = s · E_white(P)
```

Для координат фигуры `f ∈ {0,…,7}` — файл a…h, `r ∈ {0,…,7}` — ранг относительно своего края. Для чёрных ранг зеркалится: `r = 7 − rank`. Центральность:

```text
C(f,r) = 14 − |2f − 7| − |2r − 7|     # от 0 до 12
```

## 2. Материал и фаза игры

| Фигура | MG, cp | EG, cp | Вес фазы |
| --- | ---: | ---: | ---: |
| Пешка | 100 | 120 | 0 |
| Конь | 320 | 310 | 1 |
| Слон | 335 | 330 | 1 |
| Ладья | 500 | 520 | 2 |
| Ферзь | 950 | 930 | 4 |
| Король | 0 | 0 | 0 |

MG — дебют/миттельшпиль, EG — эндшпиль. Фаза `φ = min(24, Σ веса всех фигур обеих сторон)`. В начальной позиции φ=24. Продвижение пешки в фигуру может поднять фазу, но не выше 24.

Для каждой стороны отдельно складываются материал `M`, размещение `S`, подвижность `A`, пешечная структура `P`, пара слонов `B`, ладейные файлы `R`, безопасность короля `K`. Разность — белые минус чёрные:

```text
MG = Δ(M_MG + S_MG + A_MG + P_MG + B_MG + R_MG + K_MG)
EG = Δ(M_EG + S_EG + A_EG + P_EG + B_EG + R_EG + K_EG)
E_white = trunc((φ·MG + (24−φ)·EG) / 24) + 12·s
```

`trunc` отбрасывает дробную часть к нулю, сохраняя цветовую симметрию. Бонус темпа — 12 cp стороне хода. Терминальные состояния в поиске имеют приоритет над статической формулой.

## 3. Размещение фигур

Здесь `I[условие]` равно 1 при выполнении условия и 0 иначе. Слагаемые применяются к каждой фигуре.

| Фигура | MG | EG |
| --- | --- | --- |
| Пешка | `9r + 2C` | `12r + 2C` |
| Конь | `7C − 12I[r=0] − 8I[f∈{0,7}]` | `6C − 12I[r=0] − 8I[f∈{0,7}]` |
| Слон | `4C + 3r` | `5C` |
| Ладья | `2r + 18I[r=6]` | `3C` |
| Ферзь | `C − 6·max(0,r−2)` | `4C` |
| Король | `−4C − 8r + 32I[r=0 ∧ f∈{2,6}]` | `8C` |

Это простые генерируемые piece-square таблицы, не заимствованные обученные таблицы. Король тяготеет к укрытию при наличии тяжёлых фигур и к центру в эндшпиле. Раннее продвижение ферзя немного штрафуется.

## 4. Подвижность и безопасность

Подвижность фигуры — число атакуемых клеток, не занятых своими фигурами и не атакованных пешками противника. Это псевдоподвижность для оценки, а не список легальных ходов; например, связки здесь не исключаются. Легальность полностью проверяется на уровне поиска.

| Фигура | MG cp / клетку | EG cp / клетку |
| --- | ---: | ---: |
| Конь | 4 | 2 |
| Слон | 4 | 3 |
| Ладья | 2 | 4 |
| Ферзь | 1 | 2 |

Для короля считается кольцо соседних клеток. Каждая клетка кольца, атакованная хотя бы одной фигурой противника, штрафует на 10 MG / 2 EG cp. Каждая своя пешка на следующем ранге перед королём в его файле или соседнем даёт +10 MG cp. Эндшпильный бонус щита — 0.

## 5. Пешки, слоны, ладьи

- Каждая лишняя пешка на файле: −18 MG / −12 EG cp.
- Каждая изолированная пешка, у которой нет своей пешки на соседних файлах: −14 MG / −18 EG cp.
- Защищённая своей пешкой пешка: +8 MG / +12 EG cp.
- Проходная пешка, перед которой нет пешек противника на своём и соседних файлах: `+4r² MG / +8r² EG` cp.
- Наличие двух или более слонов: один бонус +28 MG / +40 EG cp.
- Ладья на полуоткрытом файле без своих пешек: +12 MG / +10 EG cp.
- Ладья на полностью открытом файле без пешек обеих сторон: +22 MG / +18 EG cp.

## 6. Поиск: negamax и alpha-beta

Для множества легальных ходов `L(P)`:

```text
V(P,d,α,β) = max по m∈L(P) { −V(P после m, d−1, −β, −α) }
α = max(α, найденная оценка)
если α ≥ β, оставшиеся ветви не нужны
```

Терминальные оценки:

```text
мат стороне хода: −30000 + ply
пат / недостаточный материал / повторение 3 раза / 100 полуходов: 0
```

Бонус расстояния предпочитает более быстрый выигрыш и более позднее поражение. Мат имеет приоритет над 50-ходовым счётчиком. При сохранении mate-score в TT расстояние нормализуется относительно текущего ply.

Итеративное углубление выполняет глубины 1, 2, 3, … до лимита. Сохраняется только **целиком завершённая** корневая итерация. Если даже глубина 1 не завершена, возвращается заранее выбранный легальный ход из порядка ходов, с `depth=0`; статическая оценка в этом случае относится к текущей позиции, а не доказывает качество fallback-хода.

В корне каждый ход ищется с полным окном `[-32000,+32000]`: это дороже общего корневого alpha, зато оценки всех кандидатов на одной глубине сопоставимы и не являются лишь границами от отсечения. Внутри каждого поддерева alpha-beta работает обычным образом.

### Стабилизация взятий: quiescence

При `d=0` поиск не обрывается посреди обмена. Если шаха нет, статическая оценка служит stand-pat; далее рассматриваются легальные взятия и превращения. При шахе рассматриваются **все** уходы от шаха, включая тихие; stand-pat запрещён.

Обычный предел — 8 дополнительных полуходов. Шаховые продолжения могут продлить его, но есть абсолютный предел 64 ply. На абсолютной границе возвращается статическая оценка; это ограничение качества, а не разрешение сделать нелегальный ход. При нехватке времени поиск прерывается раньше.

### Порядок ходов

1. Ход из TT: приоритет 1 000 000.
2. Превращение: `150000 + цена новой фигуры`.
3. Взятие: `100000 + 16·цена жертвы − цена атакующего` (MVV-LVA); en passant учитывается как взятие пешки.
4. Тихий killer-ход, ранее давший отсечение на том же ply: +20 000.
5. History-бонус: сумма `depth²` за тихие отсечения, ограниченная 10 000.
6. Разность MG piece-square бонусов после и до хода.

Приоритеты складываются, кроме немедленного возврата для TT-хода. Два killer-хода хранятся на каждый ply. При равенстве приоритетов порядок стабилен по UCI.

### Таблица транспозиций и повторения

Ключ позиции состоит из точных битовых масок фигур, цвета хода, прав рокировки и **легального** en passant. Это не вероятностный Zobrist-хеш. Ключ TT дополнительно включает 50-ходовый счётчик и набор счётчиков позиций истории. Поэтому одинаковый FEN с разной историей повторений не получает неподходящую оценку из кэша.

При начальной реконструкции история до необратимого хода отбрасывается; внутри дерева счётчики обновляются push/pop. Запись TT: глубина, оценка, тип границы (`exact/lower/upper`) и лучший ход. До 15 000 записей по умолчанию; новая корневая задача очищает кэш. Это консервативное решение корректности: оно даёт меньше совпадений, чем агрессивные таблицы сильных движков.

## 7. Контролируемая непредсказуемость

Пусть лучший результат завершённой итерации равен `v*`. В пул попадают максимум три первых хода с оценкой `vᵢ ≥ v* − ε`, где по умолчанию `ε=20 cp`. Вероятность выбора:

```text
wᵢ = exp((vᵢ − v*) / T)
Pr(mᵢ) = wᵢ / Σⱼwⱼ
T = 8 cp по умолчанию
```

Например, для оценок `50, 40, 34`:

```text
w = [1, exp(−10/8), exp(−16/8)] = [1, 0,2865, 0,1353]
Pr ≈ [70,33%, 20,15%, 9,52%]
```

Шум не добавляется к листовым оценкам и не вмешивается в рекурсию. Явный mate-score вообще не рандомизируется. `--noise 0` выбирает строго лучший найденный ход. Предел 20 cp относится **к текущей оценке поиска**, а не является гарантией истинной силы: неглубокий поиск тоже может ошибаться.

`--seed` фиксирует генератор случайных чисел. Для полной воспроизводимости нужны также одинаковые завершённая глубина/бюджет узлов: при ограничении секунд более быстрая машина может успеть глубже.

## 8. Время

Коннектор измеряет полный HTTP RTT монотонными часами и вычисляет:

```text
D_local = t_received + (deadline_server − serverNow)/1000 − RTT − reserve
left = max(0, D_local − monotonic_now)
reserve = 0,3 секунды по умолчанию
```

Из общего запаса берётся ориентир на 35 будущих ходов:

```text
target = max(0,02, remaining_total/35 + increment/2)
search_seconds = max(0, min(max_think, target, 0,9·left))
max_think = 1,8 секунды по умолчанию
```

Восстановление истории и проверка FEN происходят до вычисления финального `left`. Счётчик времени проверяется перед каждым корневым ходом и каждые 16 узлов. Это мягкий программный дедлайн: небольшое превышение возможно из-за обработки узла и планировщика ОС. Сетевой запас и коэффициент 0,9 оставляют место для отправки хода; на перегруженной машине или медленной сети их стоит увеличить/снизить max-think. Серверный предел остаётся окончательным.
