# DeepSpeedBot

**«Я уже сходил. Теперь твоя очередь думать».**

Отдельный авторский C++20-движок для DeepMove: свои шахматные правила, оценка, поиск и предварительный расчёт во время хода соперника. Нет Stockfish, NNUE, чужих оценочных таблиц, облачного ИИ, шахматных API или дебютной книги. Существующий Python DeepMoveBot не изменён.

Это рабочий эксперимент. Выигрыш от скорости измеряется; гипотеза, что сохранение сложности повышает вероятность победы **по времени**, пока не подтверждена. Результаты, ограничения и PGN — в [VALIDATION.md](docs/VALIDATION.md).

## Быстрый старт на Windows

Из корня репозитория:

```powershell
# Только если нет своего C++20-компилятора и CMake:
& .\DeepSpeedBot\scripts\bootstrap.ps1
& .\DeepSpeedBot\scripts\build.ps1

# Токен вводится скрыто. Процесс движка живёт всю партию.
python .\DeepSpeedBot\run.py --game GAME_UUID --side w --single-core
```

`bootstrap.ps1` скачивает проверяемые SHA-256 переносимые архивы [w64devkit](https://github.com/skeeto/w64devkit/releases/tag/v2.11.0) и [CMake](https://github.com/Kitware/CMake/releases/tag/v4.5.0) в `DeepSpeedBot/.tools`. Нет установщика, записи в реестр, постоянного изменения PATH или глобальных Python-пакетов. Во время сборки PATH меняется только у текущего процесса и восстанавливается. Инструменты занимают заметно больше места, чем бот; после работы их можно убрать:

```powershell
& .\DeepSpeedBot\scripts\clean-tools.ps1
```

Исходники и `build/deepspeed.exe` сохраняются. Повторная сборка после очистки требует снова выполнить bootstrap. Сам готовый бот не требует компилятора или GCC DLL. В этом рабочем каталоге инструменты удалены после проверки; исполняемый файл оставлен.

## Linux или свой компилятор

```sh
cmake -S DeepSpeedBot -B DeepSpeedBot/build -DCMAKE_BUILD_TYPE=Release
cmake --build DeepSpeedBot/build --parallel
ctest --test-dir DeepSpeedBot/build --output-on-failure
python3 DeepSpeedBot/run.py --url https://arena.example --game GAME_UUID --side b --single-core
```

Нужны CMake ≥3.20, C++20 с потоками и Python ≥3.10. Production-зависимостей Python нет. Сборка: `-O3` у GCC/Clang, `/O2` у MSVC. Базовый бинарник x86-64 переносимый; `-DDEEPSPEED_NATIVE=ON` включает оптимизацию под текущий CPU и уменьшает переносимость. Linux предусмотрен исходниками/CMake, но локально проверялась Windows x64, не Linux.

## Подключение к арене

1. На `/arena` создать профиль, партию с местом «Бот» и пригласить второй аккаунт.
2. Для регламента из ТЗ выбрать **свой формат: 300 секунд, 0 добавления, 3 секунды на ход бота**. Стандартная «Арена» по-прежнему даёт 600 секунд; бот учитывает фактические часы любого формата.
3. Выпустить ключ своего места и запустить `run.py`. Ключ не передаётся аргументом процесса. Для автоматизации используется `DEEPSPEED_BOT_TOKEN`; перед запуском C++-процесса переменная удаляется из его окружения.
4. Оба бота вызывают `ready`; сервер выдерживает обратный отсчёт. Зрителям достаточно обычной ссылки на партию.

```sh
python DeepSpeedBot/run.py --url http://127.0.0.1:3000 --game GAME_UUID --side w \
  --mode adaptive --ponder adaptive --single-core --log DeepSpeedBot/reports/live.jsonl
```

Полный [протокол и пример подключения](docs/CONNECTOR.md). Игра продолжается на сервере при отключении клиента. `Ctrl+C` останавливает локальный процесс, не сдаёт партию.

Для **HardBullet Arena** при создании партии выберите режим `hardbullet`: 15 секунд каждому, без добавления, до 1 секунды на ход. Клиент запускается той же командой; он берёт реальный deadline из API и уменьшает поиск с учётом остатка общего времени и сетевого запаса. Pondering продолжает работать в чужую очередь; предстартовый отсчёт не расходует игровые 15 секунд.

## Режимы и параметры

| `--mode` | Поведение |
| --- | --- |
| `speed` | Короткий целевой поиск, шахматная оценка без бонусов сложности |
| `survival` | Предпочтение сохранению материала и сложности среди близких ходов |
| `pressure` | Максимальный ограниченный бонус сложности/сохранения напряжения |
| `balanced` | Умеренная фиксированная сила предпочтений |
| `adaptive` | Сила предпочтений зависит от наблюдаемого времени соперника и его часов |

`--ponder off|single|multi|adaptive` управляет предварительным расчётом отдельно от стиля. Кэшируется до восьми веток; по умолчанию три. Ponder hit с полностью завершённой глубиной ≥2 возвращает подготовленный легальный ответ без нового поиска. При промахе остаётся TT, запускается обычный ограниченный поиск.

Коэффициенты — в [config/default.conf](config/default.conf), передаются через `--config`. `--think-ms` задаёт экспериментальный предел поиска вместо адаптивного; серверный дедлайн остаётся верхней границей. `--reserve-ms` задаёт сетевой запас клиента (220 мс по умолчанию). Однопоточный поиск работает и без affinity; `--single-core` дополнительно привязывает нативный процесс к одному разрешённому логическому CPU.

Поиск: итеративный Negamax, Alpha-Beta/PVS, quiescence с полными уходами от шаха, сортировка взятий, killer/history, проверяемое late move reduction, ограниченная таблица транспозиций. На каждом завершённом уровне сохраняется лучший ход; прерывание не публикует частичный уровень. Уникальный легальный ход возвращается сразу. Стиль не выбирает найденное проигрывающее матовое продолжение вместо нематового и не отклоняется от лучшей рассчитанной оценки больше `safe_loss_cp`.

[Формулы и ограничения оценки](docs/FORMULAS.md).

## Проверки и измерения

```sh
python -m unittest discover -s DeepSpeedBot/tests -p test_protocol.py -v
python DeepSpeedBot/scripts/benchmark.py
```

Независимая проверка правил и матчевые серии используют уже существующее окружение DeepMoveBot, а не подключают его к ядру:

```powershell
& .\DeepMoveBot\.venv\Scripts\python.exe DeepSpeedBot/tests/differential.py
& .\DeepMoveBot\.venv\Scripts\python.exe DeepSpeedBot/scripts/matches.py --games-per-variant 8
node DeepSpeedBot/scripts/arena-smoke.mjs
```

На Linux путь к Python обычно `DeepMoveBot/.venv/bin/python`; для API-теста можно задать `DEEPMOVE_BOT_PYTHON`. Альтернатива — отдельное тестовое venv и `pip install -r DeepSpeedBot/tests/requirements.txt`; импорт учебного соперника берётся из соседней папки репозитория.

`matches.py` проводит 64 локальные партии: восемь вариантов × восемь игр, смена цветов и четырёх дебютных начал, одинаковые целевые 20 мс поиска, 300 секунд суммарно, предел хода 3 секунды. Предел длины 240 полуходов — только ограничение этого измерения: незавершённое не считается ничьёй. `arena-smoke.mjs` запускает настоящий Next.js-сервер на 3127 с отдельной SQLite, играет две полные партии через API, сохраняет серверный PGN и проверяет отсутствие таймаутов. Пользовательская база и сервер на 3000 не затрагиваются.

Тесты включают perft до 4 865 609 узлов в начале, Kiwipete до 4 085 603, хеши make/unmake, pinned en passant, все превращения, мат/пат/повторения/50 ходов, быстрые THINK↔PONDER, hit/miss, UCI ponderhit/stop, жёсткий бюджет, URL/redirect/token-защиту. Отчёты создаются в игнорируемой `reports`; компактные реальные результаты и PGN зафиксированы в `docs/validation`.

## Структура

- `include/deepspeed`, `src` — board, evaluation/strategy/opponent model/time manager, search/TT, persistent engine/protocol.
- `adapter` — управление C++-процессом и HTTP-коннектор стандартной библиотеки Python.
- `run.py` — удобный CLI клиента.
- `config` — ограниченные и проверяемые коэффициенты.
- `scripts`, `tests` — сборка, очистка переносимых инструментов, измерения и проверки.
- `docs` — формулы, протокол, измеренные результаты.

Полноценного Elo-рейтинга, доказанной модели времени чужого алгоритма, SMT-специфичной настройки, magic bitboards, нейросетей и tablebases нет. Автоматический лимит 400 полных ходов отсутствует на текущем сервере; не следует выдавать локальный ply limit за серверное правило. Собственный клиент поддерживает до 1500 полуходов истории, с запасом для 400 полных ходов.
