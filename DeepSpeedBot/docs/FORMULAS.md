# Математика DeepSpeedBot

Формулы авторские и открыты для настройки. Общие Alpha-Beta, bitboard, Zobrist, PVS и LMR — общеизвестные алгоритмы. Материальные цены и позиционные коэффициенты ниже не взяты из чужого движка. Их текущие значения — начальная гипотеза, не результат профессионального tuning.

## Шахматная оценка

Единица — 1 centipawn. Материал: **P=100, N=320, B=335, R=500, Q=950**. Это внутренняя оценка, отличная от информационного счётчика арены 1/3/3/5/9.

Позиция оценивается со стороны очереди хода:

```text
E = S[side_to_move] - S[opponent] + 8
phase = min(24, N + B + 2R + 4Q)     # обе стороны вместе
S = material + (phase × middlegame + (24-phase) × endgame) / 24
    + activity + pawn_structure + bishop_pair + rook_files + king_safety
```

Координаты приводятся к своей стороне: `x=file`, `y=rank` для белых, `y=7-rank` для чёрных. `center = 7 - (|2x-7|+|2y-7|)/2` с целочисленным делением. Таблица ниже — алгоритмическое значение клетки до интерполяции, а не заранее скопированная PST.

| Фигура | Middlegame | Endgame |
| --- | --- | --- |
| P | `5y + 3center` | `3y² + 2center` |
| N | `11center - 12[y=0]` | `7center` |
| B | `5center + 3y` | `5center` |
| R | `23`, если y=6, иначе `2y` | `3center` |
| Q | `2center - 12[y>2 и fullmove<8]` | `5center` |
| K | `-9center - 9y + 32[(x=2 или 6) и y=0]` | `12center` |

Дополнения: +28 за двух слонов; +13 ладье без своей пешки на вертикали; -10 каждой сдвоенной пешке; -11 изолированной; проходной пешке `y²(32-phase)/12`. Активность N/B/R/Q — число атакуемых клеток без своих фигур ×3 для коня, ×2 для остальных. Пешечный щит даёт `10 × shield × phase/24`. Атаки противника на кольцо короля штрафуются на 9 для ферзя, на 4 для остальных, с тем же фазовым коэффициентом. Кольцо — восемь соседних клеток.

## Сложность и предполагаемая продолжительность

Пусть `A[s]` — объединение атак стороны, `P[s]` — атаки пешек. Все следующие признаки нормализованы в [0,1]:

```text
safe = |A[w] \ (P[b] ∪ own[w])| + |A[b] \ (P[w] ∪ own[b])|
tension_count = |A[w] ∩ pieces[b]| + |A[b] ∩ pieces[w]|
locked = число белых пешек, непосредственно заблокированных чёрной пешкой впереди
exposure = Σ |king_ring[s] ∩ A[opponent]| / 8

M = clamp(safe/70)
T = clamp(tension_count/12)
K = clamp(exposure/2)
C = clamp(0.30M + 0.30T + 0.20K + 0.20clamp(locked/4))
L = clamp(0.65 × non_pawn_non_king_pieces/14
        + 0.25 × pawns/16 + 0.10 × locked/4)
```

Это не просто число легальных ходов: учитываются безопасная активность, атакованный материал, напряжение вокруг королей и пешечные блокировки. `L` — прокси сохраняющейся сложности, а не предсказание числа оставшихся ходов. Никакой гарантии, что конкретный соперник будет считать такую позицию дольше, нет.

## Выбор безопасного стиля

На каждом полностью завершённом уровне считаются отдельные полные оконные оценки корневых ходов. Стилевое предпочтение:

```text
B = pressure × [complexity_cp × (C_after-C_before)
                + longevity_cp × (L_after-L_before)
                - exchange_cp × is_capture]
   - risk_cp × max(0,K_after-K_before)
   - 20[draw_after и adaptive_pressure>0.4]
U = search_score + B
```

Выбирается максимум U **только** среди ходов не далее `safe_loss_cp=18` от лучшей шахматной оценки. При найденной матовой оценке стилевой выбор отключён. Матовые проигрыши не включаются в нематовый пул. Оценка угроз шахматная, глубина ограничена: это не доказательство отсутствия более далёкой тактики. `K` учитывает оба короля и консервативно штрафует рост общей экспозиции; это упрощение.

`speed`: B=0. `balanced`: pressure=0.5; `survival`: 0.8; `pressure`: 1. `adaptive` после трёх наблюдений использует:

```text
slow = clamp((opponent_mean_ms-60)/700)
low_clock = clamp((45000-opponent_remaining_ms)/45000)
pressure = clamp(0.7slow+0.3low_clock)
```

До трёх наблюдений pressure=0.25. Быстрый соперник с достаточными часами уменьшает стилевую составляющую до нуля. Основная шахматная оценка и матовые приоритеты сохраняются во всех режимах.

## Наблюдение за соперником

Используются только публичные `moves[].elapsedMs`, `remainingMs`, SAN и история. Среднее/дисперсия обновляются алгоритмом Welford. Отдельно хранятся средние на шахах, взятиях, тихих ходах и в трёх фазах. В API `elapsedMs` включает сеть, polling и серверную обработку; это наблюдаемая задержка ответа, не чистое CPU-время чужого поиска.

Измеряется корреляция Пирсона `r = covariance(C,time)/sqrt(M2_C × M2_time)`. Матчевый скрипт сохраняет C и фактическую задержку каждого хода для проверки расчёта. Корреляция не доказывает причинность; фазовые изменения и бюджет времени — существенные смешивающие факторы. Для pressure сейчас используются среднее время и остаток, остальные признаки служат телеметрией и основой дальнейших экспериментов.

## Бюджет своего хода

Коннектор вычисляет монотонный безопасный остаток:

```text
hard = deadline - serverNow - elapsed_since_receive - observed_RTT - reserve_ms
remaining = clocks[side] - (serverNow-turnStartedAt)
```

`reserve_ms=220` у клиента; RTT вычитается полностью. Нативный менеджер получает уже безопасный hard. Стандартный UCI без hardtime использует потолок `3000-config.reserve_ms`.

```text
base = 18 для speed, иначе normal_ms=70
desired = base × (0.65+C)
если шах, K>0.45 или |E|>220: desired=critical_ms=450
expected_moves = max(25,100-fullmove/2)
sustainable = remaining/expected_moves + increment/2
если remaining<5000: sustainable=max(1,remaining/80)
budget = clamp(min(desired,sustainable,hard),1,hard)
```

Это консервативная эвристика: большая материальная оценка тоже может включать критический бюджет. В тестах `--think-ms` заменяет desired фиксированным целевым временем. Уникальный легальный ход и найденный мат завершают поиск раньше; ponder hit отправляется сразу. Если транспортный запас уже исчерпан, клиент отправляет первый официальный легальный ход без нового поиска. При реально истёкшем серверном времени этот запрос всё равно не спасёт партию.

Отмена проверяется атомарно на каждом узле, часы — каждые 128 узлов. Перерасход ограничен длительностью небольшой пачки узлов, но ОС и сеть не дают абсолютной real-time гарантии. Сохраняется последний полностью рассчитанный уровень и легальный начальный fallback.

## Поиск, TT и pondering

Negamax/PVS с Alpha-Beta. LMR уменьшает глубину на один только после четырёх ходов на глубине ≥3: тихий ход, без превращения/взятия/шаха, не hash move. Улучшение alpha обязательно перепроверяется на полной глубине. Quiescence в шахе перебирает **все** легальные уходы, иначе взятия и превращения. Пат не оценивается stand-pat. Максимальная поисковая высота 96 полуходов.

TT хранит move/score/depth/bound/age. Размер — ближайшая снизу степень двойки записей в заданном бюджете (при Hash=32 на этой сборке около 24 МиБ записей). Нет выделений памяти на узел. Zobrist — детерминированный SplitMix64. Помимо позиции, search key включает полусчётчик и rolling fingerprint обратимой истории. Это снижает переиспользование некоторых транспозиций, зато разделяет разные контексты повторений. Как и любой 64-битный хеш, это вероятностная идентичность, не математическое исключение коллизий. EP входит в ключ только при легальном взятии, включая проверку связки.

После собственного подтверждённого хода ранжируются ответы соперника по быстрой шахматной оценке. `single` анализирует верхний, `multi` — round-robin по верхним N, `adaptive` — выбирает максимальный приоритет:

```text
p_i ∝ exp(clamp((score_i-max_score)/80,-8,0))
priority_i = p_i × (1+C_i)/(1+visits_i)
```

Это эвристические веса, не обученные вероятности. Каждый slice по умолчанию 35 мс, общая TT сохраняется. Кэш ответа привязан к **позиции и истории после конкретного ответа соперника**; hit проверяет легальность и завершённую глубину ≥2. Несовпадение сразу отменяет pondering, ждёт короткое завершение текущей пачки и переключается на актуальную позицию. Поиск в одном worker, основной поток ждёт stdin; нет доступа к чужим процессам, искусственного торможения, скрытого I/O или дополнительных поисковых ядер.
