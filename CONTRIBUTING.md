# Участие в разработке

DeepMove открыт для исправлений, новых алгоритмов и улучшений интерфейса.
Для крупной возможности сначала опиши задачу в issue, чтобы согласовать
поведение и границы изменений.

## Подготовка

```sh
git clone https://github.com/Kait20-dev/DeepMove.git
cd DeepMove
npm ci
git switch -c feature/my-change
npm run dev
```

Нужен Node.js 24+. Перед изменением Next.js прочитай `AGENTS.md` и
соответствующий раздел `node_modules/next/dist/docs/`.

Не добавляй в Git зависимости, БД, ключи, `.env`, компиляторы, venv,
готовые бинарники и диагностические логи с приватными данными.

## Структура изменений

- UI и правила арены: `src/features/arena`.
- Сервер, авторизация и SQLite: `src/server`.
- API: `src/app/api/arena/[[...path]]/route.ts`.
- Статический лендинг: `site/index.html` и `site/assets`.
- Тексты документации: `docs/*.md`; её меню: `site/pages.mjs`.
- Примеры участников: `clients`, `DeepMoveBot`, `DeepSpeedBot`.

Не меняй формат существующих партий без обратной совместимости.
Секретные поля должны оставаться вне публичных представлений и PGN.
Изменение правил, часов или результатов требует содержательных тестов.

## Проверки платформы

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

Для UI и интеграции после build:

```sh
npm run test:e2e
```

Нужны установленный Google Chrome и Python 3.10+. Скрипт поднимает сервер
на порту 3107 с отдельной БД в `test-results`, проверяет реальные процессы
коннекторов и останавливает сервер. Пользовательские данные не затрагиваются.

## Проверки сайта

```sh
npm run build:pages
npm run check:pages
npm run test:pages
```

Статическая проверка проверяет ссылки, якоря и опубликованные файлы.
Браузерная — размеры экранов, меню, поиск, копирование, паузу анимации и
режим reduced motion. Скриншоты остаются в `test-results`.

## Pull request

В описании укажи:

1. Какую проблему решает изменение и как его проверить.
2. Что поменяется для участника или зрителя.
3. Какие проверки пройдены; для интерфейса приложи скриншот.
4. Нужны ли настройки, миграции или обновление документации.

Держи изменения в тематической ветке. Не смешивай изменение шахматных
правил с чисто визуальным оформлением. Коммиты должны объяснять результат.
